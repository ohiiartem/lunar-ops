# Отчёт: профили горизонта по LOLA (R01, R11, R23)

## Что сделано
- `backend/calc/dem.py`: чтение GeoTIFF-тайла (PIL + numpy, без rasterio), проекция широта/долгота ↔ полярная стереографическая (формулы LOLA), билинейная выборка.
- `backend/calc/horizon.py`: `horizon_profile(dem, lat, lon, radius_m, n_az, observer_height_m)` → углы рельефа по азимутам (от севера по часовой, как в Horizons) и покрытие DEM по каждому азимуту. `blocked_by_terrain(profile, az, el)` отвечает «Солнце закрыто рельефом?».
- `backend/calc/build_profiles.py`: строит `data/profiles/<id>.json` и `index.json` («рельеф: да/нет») для всех площадок из `sites.py`. Запуск:
  `cd backend && python3 -m calc.build_profiles --tiles ~/Downloads --out ../data/profiles` (меньше секунды на 3 площадки).

## Данные (что нашлось вместо одного файла DEM)
Для каждой площадки есть свой тайл `SiteXX_final_adj_5mpp_surf.tif`: 5 м на пиксель, сфера R = 1 737 400 м, центр тайла совпадает с координатами площадки из Data Book (проверено тестом, отклонение ≤ 1,5 пикселя).

| Площадка | Тайл | Высота точки | Покрытие по азимутам |
|---|---|---|---|
| R01 Connecting Ridge | 16×16 км | 1945 м | 8,0–11,2 км |
| R11 de Gerlache Rim 1 | 16×16 км | 1794 м | 8,0–11,3 км |
| R23 Malapert Massif | 21×21 км | 4784 м | 10,5–14,8 км |

Профили (горизонт, градусы): R01 от -4,06 до 4,86 (среднее 0,87); R11 от -1,70 до 4,59 (среднее 1,09); R23 от -2,62 до 6,06 (среднее 3,02).
Так как Солнце у полюса стоит на 1,4–1,65°, рельеф закрывает его по значительной части азимутов (доля азимутов с горизонтом ниже 1,65°: R01 53%, R11 61%, R23 29%). Это не готовый результат по освещению, а только входные данные для Combine.

## Ограничения (в README и на слайд)
1. **Радиус.** Горизонт считается только по тайлу (около 8–15 км). Дальние хребты не видны. Внутри тайла горизонт R01 и R11 полностью определяется ближними 2 км, а у R23 дальние 4–6 км ещё добавляют до 0,9°. Что за пределами тайла, мы не знаем, поэтому можем только занижать горизонт, а не завышать.
2. **Наблюдатель на поверхности** (высота 0, параметр `observer_height_m`). Реальный модуль и мачта стоят выше.
3. **Проекционная погрешность.** Расстояния по плоскости проекции, ошибка менее 0,1%.
4. **Кривизна Луны** учтена приближением d²/(2R).
5. **Точка площадки** взята из Data Book (точность 5–10 м). Если рядом кратер или гребень, угол меняется. Профиль чувствителен к положению точки (не измерено).
6. **Площадки без тайла** считаются по ровной сфере (terrain: нет), интерфейс обязан это показывать.

## Проверки
10 тестов (`python3 -m unittest discover -s tests`), все проходят:
- проекция туда и обратно (4 точки, 9 знаков);
- плоский рельеф даёт горизонт 0;
- синтетическая стена высотой 100 м в 2 км даёт расчётный угол (допуск 0,05°) в азимутах 0/90/180/270 при долготе 0 и при долготе 90 (проверка поворота сетки);
- сверка направления азимута с независимой формулой большого круга: расхождение 6,4 м на 5 км;
- границы тайла, площадка вне тайла (ошибка), перехват через 0/360;
- реальные тайлы: площадка в центре тайла, профили конечны и разумны, покрытие не менее 7,9 км.

## Что НЕ проверено
- Профиль не сверен с независимым расчётом (Quickmap, Horizons или чужим кодом). Это следующая проверка: взять один азимут и сравнить с картой.
- Высоты тайла принимаются как «над сферой 1 737 400 м»; это следует из GeoKey, но не из описания файла.
- Время расчёта и память проверены только на этих трёх тайлах.
- Не подключено к Combine/Metrics и к API.
- Ещё нет 4-й и 5-й площадки: тайлов для них нет, они остаются «terrain: нет».
